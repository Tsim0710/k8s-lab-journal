---
title: CI на pull request — ворота, которые проверены на красный
steps: [3-2]
---

У сервиса `notes` появился CI: каждый pull request проходит линтер, тесты на настоящем Postgres и
сборку образа с проверкой Trivy. Дальше, в 3-3, по этим воротам пойдёт выкатка в кластер.

## Простыми словами

Раньше код проверялся только на ноутбуке и только если не забыть. Теперь на каждый PR GitHub сам
запускает три проверки параллельно, весь прогон — около 2.5 минуты:
- **lint** — статический анализ: ошибки, которые никто не проверил, незакрытые ответы, сервер без
  таймаутов;
- **test** — тесты на Postgres, который поднимается рядом на время прогона;
- **image** — сборка образа тем же Dockerfile, что для кластера, и Trivy: нет ли известных
  уязвимостей, для которых уже вышло исправление.

Ворота ценны не тем, что зелёные, а тем, что краснеют, когда должны. Это проверено отдельно.

## Что сделали

- **Workflow** — три джобы параллельно, токен прогона только на чтение, новый пуш в PR отменяет
  старый прогон. Прогон на `main` тоже есть — ради кэша: PR видит кэш своей ветки и `main`.
- **Тесты с базой** — Postgres сервис-контейнером с healthcheck, `go test -race`. Тест без базы
  раньше тихо пропускался; в CI это был бы зелёный прогон без единой проверки. Теперь при `CI=true`
  без базы он падает.
- **Trivy** краснеет только на HIGH и CRITICAL, для которых есть фикс. Иначе ворота краснели бы на
  том, что чинить нечем, и их бы скоро выключили.
- **Все actions прибиты полным SHA коммита.** В марте 2026 у trivy-action перевесили 76 из 77 тегов
  на вредоносный коммит, крадущий секреты раннеров: кто ссылался на тег, получил его без правок у
  себя. SHA обновляет Dependabot раз в неделю, релизы моложе 7 дней не предлагаются.

## Что увидели

- **Первый же прогон — красный по делу:** 7 непроверенных ошибок в коде, написанном накануне. Одна из
  них — дыра в тестах: ответ, который не разбирался как JSON, проходил молча.
- **Провокация:** тест на обрезку пробелов сломан, стадия сборки на старом патче Go. Упали ровно
  test (`text: "купить молоко  "`) и image: Trivy нашёл 4 HIGH в стандартной библиотеке Go 1.27.0,
  исправленные в 1.27.2–1.27.3. Линтер остался зелёным — как и должен.
- Trivy видит уязвимости stdlib в distroless-образе, где пакетов ОС почти нет: он читает из бинаря
  версию компилятора и модулей.
- **«CACHED» не значит «быстро»:** сборка со всеми слоями из кэша — 109 с, из них 56 с — `go build`.
  Кэш слоёв не хранит кэш компилятора Go, зависимости компилируются заново на каждом прогоне.

## Что сломалось и почему

- **Первая провокация сломала больше, чем хотела.** Убрал `TrimSpace`, чтобы уронить тест, — пакет
  `strings` остался неиспользованным, код не собрался, и красными стали все три джобы. Локальная
  сборка ошибку показала, но команды шли цепочкой через `;` и пуш ушёл. Поломка для проверки ворот
  должна ломать ровно одну вещь — иначе не видно, какая проверка что ловит.
- **Обязательными проверки не сделать:** на бесплатном аккаунте защита ветки доступна только открытым
  репо. CI покажет красный, но Merge не заблокирует.

## Выводы

- Ворота надо проверять на красный, а не только на зелёный, и следить за тихими пропусками: `SKIP` в
  тестах, `continue-on-error`, `|| true`.
- Тег стороннего action — изменяемая ссылка на чужой код с доступом к секретам прогона. SHA плюс
  автоматическое обновление с задержкой.
- Порог сканера — компромисс: слишком строгий выключат, слишком мягкий не нужен. Ронять на то, что
  можно починить.
