Начался блок 3. В кластере появился первый свой код — маленький API заметок на Go с Postgres. На
нём дальше пройдут CI, выкатка через ArgoCD, миграции, SLO и canary.

## Простыми словами

До сих пор в кластере работали чужие приложения, которые уже умеют всё нужное для эксплуатации. Свой
сервис пришлось научить этому самому. Он сам отвечает на четыре вопроса:
- жив ли он — `/healthz`;
- готов ли принимать запросы — `/readyz`;
- сколько запросов, сколько ошибок, как быстро — метрики;
- что было с конкретным запросом — трейс и строки лога с тем же `trace_id`.

Образ собран из двух стадий: компилятор остаётся в первой, в итоговый образ попадает только бинарь.
Наивный вариант весил 1.9 ГБ, итоговый — 8.76 МБ, без оболочки и не от root.

## Что сделали

- **Сервис `notes`** — Go 1.27, стандартный `net/http`, pgx, client_golang, OpenTelemetry:
  - два порта: API и служебный (пробы и метрики), чтобы служебное не уехало наружу через ingress;
  - метрика — одна гистограмма с меткой маршрута по шаблону (`/api/notes/{id}`), чтобы id не плодили
    серии;
  - логи в JSON с `trace_id`, трейсы по OTLP со спаном на каждый SQL-запрос;
  - миграции goose вшиты в бинарь. Пока применяются при старте, в 3-4 переедут в отдельный Job.
- **Остановка без потерь**. По SIGTERM сервис сначала отвечает «не готов» и ждёт 5 секунд, пока его
  уберут из балансировки, потом дорабатывает начатые запросы. Сразу выходить нельзя: ingress узнаёт
  об удалении пода только через несколько секунд.
- **Тесты на настоящем Postgres**: CRUD, поиск без учёта регистра, ошибки. Отдельно проверяется, что
  при остановке readiness падает, а liveness нет.
- **В кластере** — Deployment из gitops, волна 1, после базы:
  - non-root, файловая система только для чтения, все capabilities сняты;
  - `GOMEMLIMIT` из лимита памяти, без лимита CPU;
  - ServiceMonitor и NetworkPolicy: снаружи пускает только Prometheus;
  - образ в приватном GHCR, в кластере токен только на чтение;
  - своя роль и база в общем Postgres, другим ролям подключение закрыто.
- **Секреты без редактора** — одна команда спрашивает значение скрытым вводом и сама кладёт его в
  зашифрованный файл. Пароль базы генерируется, его никто не видит.

## Что увидели на кластере

Под поднялся с первого раза, миграция заняла 6 мс. Проверка всей цепочки:
- **Prometheus** собирает метрики по маршрутам и кодам. По `notes_build_info{version="75a5412"}`
  видно, какой коммит сейчас отвечает.
- **Loki** сам распознал уровень из JSON (`INFO` → `info`), поля разбираются `| json`. Алерт
  `AppErrorLogsHigh` из 2-9 увидит ошибки сервиса без доработки.
- **Jaeger**: трейс `GET /api/notes` — 5.7 мс, из них 5.3 мс база. Спанов SQL два: при первом
  выполнении pgx готовит запрос (prepare), потом выполняет.
- Цель в Prometheus появилась через полторы минуты после пода: оператор пересобирает конфиг по новому
  ServiceMonitor. Это не поломка, но и не мгновенно.

## Что сломалось и почему

- **Кэш зависимостей сбрасывался на каждом коммите.** Во второй сборке `COPY go.mod go.sum` взялся из
  кэша, а `go mod download` пошёл заново. Строка `ARG VERSION` стояла выше, а значения ARG входят в
  ключ кэша всех `RUN` ниже объявления. VERSION — sha коммита, он новый каждый раз. Комментарий в
  Dockerfile при этом обещал ровно обратное. ARG перенёс туда, где он нужен.
- **Пользователь в образе был задан именем.** В distroless `:nonroot` пользователь задан числом 65532,
  а мой `USER nonroot:nonroot` перекрыл его именем. С `runAsNonRoot` kubelet по имени не может
  проверить, что это не root, и не запускает под. Поймал, когда писал манифест, до выкатки.
- **Пакет в GHCR без привязки к репо** был бы чужим для GitHub Actions того же репо: в 3-3 CI получил
  бы 403 на пуш. Метку `org.opencontainers.image.source` поставил до первого пуша.

## Выводы

- Сервис, удобный для эксплуатации, — это не «добавить /metrics». Это решения на каждом шаге:
  - что проверяет каждая проба;
  - как он останавливается;
  - какие метки у метрик, чтобы не взорвать кардинальность;
  - как связать лог с трейсом.
- Ошибки в Dockerfile видны по выводу сборки: какой шаг `CACHED`, а какой нет. Комментарий в файле —
  не доказательство.
- Ловушки с безопасностью пода (числовой UID, приватный registry) дешевле поймать при написании
  манифеста, чем разбирать `CreateContainerConfigError` после выкатки.
