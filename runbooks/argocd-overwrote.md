## Простыми словами

ArgoCD с `selfHeal` постоянно приводит кластер к виду из git. Всё, что поправлено руками мимо git,
он вернёт обратно. Хуже, когда объект в git неполный, а содержимое дописывается в рантайме: любое
изменение такого объекта ArgoCD «починит» до пустого вида из git.

## Как разбирать

1. Что изменилось: `kubectl -n argocd get application <app> -o json | jq '.status.operationState'` —
   последний синк, когда и что
2. История приложения: `kubectl -n argocd get application <app> -o json | jq '.status.history'`
3. Объект сейчас и в git — сравнить руками или `helm template` с теми же values

## Как чинить

- Правка руками была нужна — перенести её в git
- Объект заполняется в рантайме (секрет с ключами, сгенерированные поля) — вернуть содержимое (из
  бэкапа или перезапуском того, кто его заполняет) и добавить `ignoreDifferences` на эти поля вместе
  с `RespectIgnoreDifferences=true`

## Чтобы не повторилось

Перед массовой операцией в GitOps-кластере (перешифровка, массовый `replace`, переразметка) проверить,
какие объекты принадлежат ArgoCD и чьё содержимое пишется в рантайме, а не берётся из git.

## Было у нас

19.10: перешифровка секретов массовым `kubectl replace` — для ArgoCD это «объект изменился»,
`selfHeal` за две секунды вернул `argocd-secret` к пустому виду из чарта, вход в ArgoCD сломался.
Лечение — рестарт argocd-server и пароль admin из хранилища доступов, защита — `ignoreDifferences`.
